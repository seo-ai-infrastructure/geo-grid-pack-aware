# Geo-Grid Rank Tracker Go-Live Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Put the fixed DuoPlus RPA template and hardened scan pipeline live and verify one full scan end-to-end.

**Architecture:** The Next.js app on Vercel (`geo-grid` project, prod URL `https://geo-grid-rose.vercel.app`) dispatches DuoPlus RPA tasks to 3 cloud phones; phones POST harvests back to `/api/collect?token=…`, which chains the next point. Commit `8d93bc1` on `cursor/duoplus-mount-screen-record` contains all code + template fixes; this plan deploys them and closes the loop with a verified scan.

**Tech Stack:** Next.js 14 / Vercel CLI, Supabase (project `mvihrrewqzvqpsufzeid`, REST + service-role key from `.env.local`), DuoPlus dashboard + OpenAPI.

## Global Constraints

- The RPA template variables MUST keep these exact keys: `search_term`, `gbp_name`, `grid_label`, `grid_webhook` — `addTask` in `lib/core.js:277-291` sends exactly these; renaming any of them breaks every scan silently.
- Both `NET_REQUEST` nodes in the template MUST keep `request_url: ${grid_webhook}` — never hardcode a URL.
- Phones are `dEW12,TA5Jr,SxRDI` (`DUOPLUS_PHONE_IDS`); do not add or remove phones in this plan.
- `LEDGER_ENABLED` stays unset (credits disabled) for the verification scan.
- The Supabase schema is already live and verified (v3 columns + public `geogrid-videos` bucket) — this plan runs NO SQL.
- Never print secret values to the terminal; use `grep -c` / redirection when checking env files.
- Operator-only steps (DuoPlus dashboard UI) are marked **[OPERATOR]** — an agent must stop and hand these to Brock.

### Task 4: Clear the stuck and stale scans

**Files:**
- Read: `.env.local` (service-role key for direct REST fixes)

**Interfaces:**
- Consumes: live deployment from Task 3.
- Produces: a scans table with no orphan `queued`/zombie `running` rows, so Task 5's verification scan gets all 3 phones.

- [ ] **Step 1: List non-complete scans**

```bash
cd "/Users/brock/Downloads/grid tracker v3/geo-grid-v2-chrome"
set -a; source .env.local; set +a; U=${SUPABASE_URL//\"/}
curl -s "$U/rest/v1/scans?select=id,status,keyword,points_done,points_total,created_at&status=not.in.(complete,complete_with_failures,cancelled)&order=created_at.desc" \
  -H "apikey: $SUPABASE_SERVICE_ROLE_KEY" -H "Authorization: Bearer $SUPABASE_SERVICE_ROLE_KEY"
```

Expected: the `queued` scan `63416cde-…` plus any old `running` scans
(`e1ecc61d-…`, `005a9e0c-…` as of 2026-08-09 evening).

- [ ] **Step 2 [OPERATOR-DECISION]: Choose per scan — resume or cancel**

Nothing in this codebase writes `queued`, so scan `63416cde-…` came from
outside the app. Brock decides per scan: resume it (set `running`) or park it
(set `cancelled`). Default for the old pre-fix `running` scans: cancel — they
were dispatched against the buggy template and their remaining points will
re-run more cheaply inside a fresh scan.

- [ ] **Step 3: Apply the decisions**

```bash
# cancel a scan (repeat per id):
curl -s -X PATCH "$U/rest/v1/scans?id=eq.SCAN_ID" \
  -H "apikey: $SUPABASE_SERVICE_ROLE_KEY" -H "Authorization: Bearer $SUPABASE_SERVICE_ROLE_KEY" \
  -H 'Content-Type: application/json' -H 'Prefer: return=representation' \
  -d '{"status":"cancelled","completed_at":"now"}' | head -c 200
# or resume the queued scan instead:
#   -d '{"status":"running"}'
```

Expected: JSON echo of each patched row with its new status.

- [ ] **Step 4: Re-check and free the phones**

```bash
curl -s -X POST https://geo-grid-rose.vercel.app/api/tick | head -c 200
```

Expected: `{"ok":true,...}`; the tick also runs `cancelStaleDuoTasks`, which
cancels pending DuoPlus tasks belonging to non-running scans so all 3 phones
are idle for Task 5.

- `attempts` stays ≤ 1 for most points.
